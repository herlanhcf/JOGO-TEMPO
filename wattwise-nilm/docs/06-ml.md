# 06 — Pipeline de Machine Learning (NILM)

Objetivo: treinar, offline, um classificador pequeno que roda **quantizado int8 no
ESP32‑S3**, e um pipeline para coletar/rotular dados por instalação.

## Abordagem: NILM baseado em eventos + classificação

Não tentamos "separar sinais continuamente" (fatorial/HMM, caro). Em vez disso:

1. **Detectar eventos** de comutação (feito no firmware, `event_detector`).
2. Para cada evento, extrair um **vetor de features** (mesma definição no firmware e no
   Python — ver `ml/extract_features.py` e `firmware/src/dsp/features.*`).
3. **Classificar** o vetor com uma rede neural pequena (MLP) ou, como fallback robusto e
   sem treino, **kNN no espaço de features** (roda direto no MCU).

### Vetor de features (por evento)

| Feature | Descrição |
|--------|-----------|
| ΔP | variação de potência ativa (W) |
| ΔQ | variação de potência reativa (VAr) |
| ΔS | variação de potência aparente |
| FP_pre, FP_pos | fator de potência antes/depois |
| H1..H7 | magnitude relativa das harmônicas ímpares da corrente |
| inrush_ratio | pico de corrente / corrente estacionária no transiente |
| t_settle | tempo até estabilizar (ms) |
| sign | evento de liga (+) ou desliga (−) |

Vetor pequeno (~20 dims) → modelo minúsculo, inferência em microssegundos.

## Coleta de dados

- Firmware em "modo rotulagem": o usuário liga um aparelho, aperta o botão e escolhe o
  rótulo no app; o evento + features + janela bruta vão para o SD (`/dataset/*.csv`).
- Repetir várias vezes por aparelho, em condições diferentes.
- Datasets públicos para pré‑treino/validação: **REDD**, **UK‑DALE**, **PLAID**
  (transientes), **WHITED**. Use PLAID/WHITED por serem de alta frequência (bons p/
  assinatura de transiente).

## Treino (`ml/train_nilm.py`)

- Entrada: CSV de features rotuladas (coletadas + datasets públicos).
- Modelo: MLP [entrada → 32 → 16 → n_classes], ReLU, softmax. Alternativa 1D‑CNN se
  usar a forma de onda bruta do transiente.
- Regularização forte (dropout) — datasets NILM são pequenos e desbalanceados.
- Métrica: F1 por classe (não acurácia — classes desbalanceadas).

## Quantização e deploy

Dois caminhos:

**A) TensorFlow Lite Micro (mais simples)**
- Treinar em TF/Keras → `TFLiteConverter` com quantização int8 (representative dataset).
- Exportar `model.tflite` → `xxd -i` → array C, ou carregar do SD.
- Rodar com `tflite-micro` (kernels otimizados ESP‑NN aceleram no S3).

**B) ESP‑DL (máxima performance no S3)**
- Converter para o formato ESP‑DL; usa instruções vetoriais do S3 diretamente.
- Mais trabalho, mais rápido. Recomendado se o modelo crescer (1D‑CNN).

**Fallback sem treino:** kNN. Guarda os centróides/exemplos rotulados em flash e
classifica por distância no espaço de features normalizado. Roda no MCU, aprende
"na hora" com poucos exemplos — ótimo para bootstrap por instalação.

## Detecção de anomalia (Fase 4)

Para cada aparelho conhecido, mantenha a distribuição da sua assinatura (P, Q, harmônicas).
Deriva sustentada (ex.: geladeira com ΔP subindo semana a semana, ou FP degradando) =
alerta de manutenção preditiva. Implementável como z‑score sobre a média móvel das
features do aparelho — barato e roda na borda.
